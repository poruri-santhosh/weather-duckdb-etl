What the project does

A small, reproducible data pipeline with orchestration, data checks, persistent analytical storage, and a documented local run path.

01

Collect

Calls the Open-Meteo forecast API for current readings on the hourly schedule, or requests up to 30 days of historical hourly data on a manual run.

02

Validate

Checks required fields and numeric values, rejects duplicate city-hour records, and enforces reasonable bounds for temperature, humidity, pressure, and wind.

03

Load and analyze

Uses a DuckDB primary key and upsert to make repeated loads idempotent, then exposes hourly, daily, and city-comparison views.

Coverage and data

Each reading includes location, UTC timestamp, temperature, relative humidity, surface pressure, wind speed, and a weather code.

Pipeline flow

Three Airflow tasks run in sequence; failed tasks are retried.

TASK 01

Extract

Request current or backfill data from Open-Meteo for each location.

TASK 02

Validate

Check schema, numeric ranges, and uniqueness before loading.

TASK 03

Upsert

Write readings using the (city, timestamp) key.

STORAGE

DuckDB

Persist the local analytical database at data/weather_data.db.

ANALYTICS

SQL views

Query summarized weather trends and aligned city differences.

Data integrity and analytical outputs

Guardrails run before a batch is written to the database.

Validation checks

  • Required location, timestamp, and weather fields must be present.
  • Metrics must be finite numeric values; timestamps must parse as UTC.
  • Temperature must be between −50°C and 60°C.
  • Humidity must be between 0% and 100%; pressure must be positive.
  • Wind speed cannot be negative; city-hour keys must be unique.

DuckDB views

  • hourly_weather_summary — hourly metric averages per city.
  • daily_city_weather_summary — daily temperature min/average/max and metric averages.
  • hourly_city_weather_comparison — same-hour temperature and humidity deltas between city pairs.
  • Primary key plus upsert ensures reruns update existing city-hour records.

Run locally

On Windows, Airflow runs in its supported Linux container through Docker Desktop and WSL 2.

1 · START

docker compose up --build -d

2 · OPEN

Visit http://localhost:8080; credentials are printed in the Airflow logs.

3 · BACKFILL

Trigger the DAG with {"backfill_days": 30}, or leave it at 0 for current readings.

This is a local portfolio/demo project. Airflow availability, task success, and zero duplicates are not claimed as measured production service-level results.
